决策模型

System One / 结构化决策：给软件用的快决策层，不是聊天机器人。有闭源云 API，也有开源权重可自托管。

日常旗舰聊天与编码看 模型选型；Agent 编排看 Agent 横评；按量推理云看百科「AI 模型 API」。

最后更新：2026-09-23

这类模型是什么
决策模型（TypeSafe 称为 System One）面向程序调用：你传入状态（文本 / JSON），再声明若干固定题型，模型一次返回选择题、打分或是/否概率——带校准置信度，可直接写进分支逻辑。
  • 不做：聊天回复、写代码、写说明文、自由生成字符串。
  • 要做：分类、路由、紧急度打分、是否触发下一步、校验 LLM 输出是否可信。
  • 和「让 LLM 输出 JSON」不同：答案空间由调用方事先定死，格式上不会跑偏成散文。
闭源云 API Jev（TypeSafe） 开源权重 Laya（Apache 2.0）· NanoJev 聊天请用 LLM
和聊天 LLM 怎么选
决策模型（如 Jev）聊天 LLM（GPT / Claude / …）
输出 类型安全的选择 / 分数 / 概率 自然语言（也可约束成 JSON，但仍是生成文本）
适合 软件内大量重复的窄决策、低延迟分支 对话、写作、编码、开放式推理
不适合 需要人读的说明、代码、长文 要把答案当硬类型塞进代码且不能容忍格式幻觉时
常见用法 Agent / 工作流里的「快决策层」 主智能体、Copilot、内容生成

多数产品会两者并用：LLM 负责理解与生成，决策模型负责稳定、便宜的分拣与闸门。

Laya（Convai Innovations） 开源权重 🆕 2026-09-18
项本站已核实口径
定位 开源 System One：状态 + 题型 → 选择/打分/是否概率；不生成文本
权重 / 协议 Apache 2.0；英文 421M（ModernBERT）/ 多语 322M（mmBERT）等 checkpoint
题型 Choice / Score / Noul（与 Jev 同形）
跑法 本机 / 自托管；官方测单题约 33–40ms（T4）；无托管刊例
入口 Hugging Face · GitHub · PyPI

Apache 2.0自托管需微调才强

和 Jev 的差别：权重可下、可再训、数据不出机房；不是托管 API。官方 model card 写明：基座 checkpoint 在 typed-decisions 上接近随机，0.766 那档是微调后的；出厂概率偏自信，上线前应用自己的数据做温度校准。多选项（如 50+ 标签）默认头预算偏紧，需调 head_max_len 或分层选择。目录见 systemonemodels.org（更新至 2026-09-22）。

NanoJev 开源权重 研究复现
项本站已核实口径
定位 约 0.6B 并行决策复现：Choice / Boolean / Score；单次前向出完整分布
权重 / 协议 权重公开（HF）；代码 MIT；HF 权重页未单独声明协议，且底座为 Qwen3-0.6B（遵循上游条款）

本页故意不收的 非决策专用权重
SemIf / OpenJev、各类 open-jev：在冻结聊天 LLM上读 logits / 复现 API 外形，不算独立决策权重。daf-jev 等是 Jev 客户端工具包。普通开源聊天模型的 JSON mode / tool call 仍归 模型选型。
常见问题
能替代 Claude / GPT 写代码吗？▼
不能。决策模型不生成字符串。写代码、改仓库、解释结论仍用 LLM 或 Coding Agent。
开源和 Jev 怎么选？▼
要自托管 / 可再训 / 数据不出域 → Laya。要托管 API、少运维 → Jev（Early Access）。NanoJev 偏研究与小模型实验。不要拿冻结聊天模型的「OpenJev 式」脚本当生产决策引擎。
和「强制 JSON 输出」有何不同？▼
JSON mode 仍是自回归生成文本再解析；决策模型按题型出有界答案（常带概率）。适合闸门与路由，不适合写散文。
国内能直连 Jev 吗？▼
TypeSafe 为海外 Early Access，连通与开通以官网为准。Laya / NanoJev 走 HF / GitHub 自托管，不依赖 TypeSafe 网络。

一句话怎么用

要托管 API → Jev（闭源云）
要开源自托管 → Laya（Apache 2.0）
要小模型实验 → NanoJev
要聊天/编码 → 模型选型
